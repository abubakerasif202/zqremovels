## Sitemap index error: investigation (2026-10-30)
- **Exact Google-reported text: not obtained.** The Search Console API only returns counts (`errors: 1`, `warnings: 0`, last read 2026-10-24 10:28 UTC, last submitted 2026-10-18). The UI is needed for the message and the headless browser has no Google session (sign-in page), so the text has not been read.
- **Live sitemaps are valid.** Index plus five children all return 200 with no redirects, `Content-Type: application/xml`, no BOM, well-formed XML (parsed with a strict parser). Counts: pages 5, services 15, suburbs 48, guides 11 = 79 URLs; `sitemap-images.xml` repeats the same 79 URLs (set-identical) with 226 image entries covering 12 unique images. All 79 URLs return 200, 0 redirects, no `X-Robots-Tag`, no `noindex`; all 12 image URLs return 200 `image/webp` on the same host. `robots.txt` lists `sitemap.xml` and `ai-sitemap.xml` (the latter is valid and was never submitted to Search Console).
- **Nothing structural changed since Google's 24 Oct read.** From the 23 Oct deploy (`df6a247`) to now, `scripts/build-site.mjs` has no sitemap or lastmod changes, `vercel.json` is unchanged and `scripts/sitemap-lastmod.mjs` is unchanged; only 4 lines of `pages.json` differ and they add no routes. Only `lastmod` dates moved (26-27 Oct).
- **Child sitemaps are fine in Google's view**: 0 errors, 0 warnings, read between 18 and 27 Oct. Only the index carries the error, and the child reads on 26-27 Oct are newer than the index read on 24 Oct.
- **Assessment:** no site defect found. Most likely a stale or transient report from the 24 Oct index read, but this is inferred, not confirmed, because the error text is unread. Duplicate URLs across the page sitemaps and the image sitemap (why "158 web URLs submitted" for 79 pages) are permitted by the protocol and cannot be excluded as the trigger.
- **No site change made.** Resubmitting needs the write scope; the re-authorisation was blocked, so the sitemap has not been resubmitted.
